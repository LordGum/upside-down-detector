# Upside Down Detector

Проект для определения ориентации текста на изображении: обычная ориентация (`0°`) или перевёрнутая на `180°`.

Проект включает генерацию синтетического датасета, подготовку шрифтов и обучение классификатора на основе `ResNet18`.

## Pipeline

1. Подготовка шрифтов с помощью `fonts_generator`.
2. Генерация синтетического датасета с помощью `train_generator`. Также использовались датасеты: [RusTitW: Russian Language Visual Text Recognition](https://www.kaggle.com/datasets/hardtype/rustitw-russian-language-visual-text-recognition) и [IIIT5K-Words](https://www.kaggle.com/datasets/prathmeshzade/iiit5k-words)
3. Разделение данных на train/validation.
4. Обучение `ResNet18` с предобученными весами ImageNet.
5. Оценка по Accuracy, Brier score и F1 (confusion matrix).
6. Предсказание вероятности того, что изображение перевёрнуто на `180°`.
7. Формирование `submission.csv`.

## Генерация шрифтов

`fonts_generator` собирает системные `.ttf` и `.otf` шрифты Windows и распределяет их по категориям:

* `sans`
* `serif`
* `script`
* `other`

После этого шрифты проверяются на наличие всех необходимых символов:

* латиница;
* кириллица;
* цифры.


## Генерация датасета

`train_generator` создаёт синтетические изображения текста размером `256×64`.

Основные параметры:

```python
NUM_IMAGES = 20_000
IMAGE_SIZE = (256, 64)
SEED = 42
```

Используются два класса:

```text
0   — обычная ориентация
180 — перевёрнутая ориентация
```

Текст генерируется из латиницы, кириллицы и цифр. Длина строки — от 2 до 20 символов. Также датасет дополнительно использует еще 2 датасета, чтобы итоговый датасет был больше похож на тестовый.

Для изображений применяются различные аугментации:

* поворот;
* Gaussian Blur;
* изменение яркости;
* изменение масштаба с padding;
* JPEG compression.

Результат сохраняется в следующем виде:

```text
generated_dataset/
├── train/
│   ├── 0/
│   └── 180/
└── train.csv
```

`train.csv` содержит:

```csv
filename,angle
000000.jpg,0
000001.jpg,0
...
```

## Обучение модели

Для классификации используется `ResNet18` с предобученными весами ImageNet.

Последний слой заменён на небольшую классификационную голову:

```text
Linear
↓
ReLU
↓
Dropout(0.5)
↓
Linear
```

На момент эксперимента обучались все параметры модели.

Основные параметры:

```python
BATCH_SIZE = 64
IMG_SIZE = (256, 64)
weight_decay = 5e-4
criterion = BCEWithLogitsLoss()
```

Оптимизатор:

```text
AdamW
```

Для изменения learning rate используется:

```text
CosineAnnealingLR
```

Данные разделяются на train/validation в пропорции 80/20 со стратификацией по классу.

Один из запусков:

```text
Train: 35491
Val:    8873
Test:  20000
```

## Метрики

Во время обучения отслеживаются:

* Accuracy;
* Loss;
* Brier score;
* Classification report.

Brier score используется для оценки качества вероятностных предсказаний.

Для каждого изображения модель выдаёт вероятность:

```text
p_180 ∈ [0, 1]
```

## Результаты

В ходе экспериментов модель показала заметный разрыв между validation и test.

В одном из запусков на validation:

```text
Epoch 8
Train Acc: 0.9711
Val Acc:   0.9213
Val Brier: 0.0612
```

При этом итоговый Brier score на тестовых данных составил:

```text
0.30781285
```

Это указывает на существенное ухудшение качества при переходе от validation к тестовым данным.

Одной из рассматриваемых причин является отличие синтетического датасета от реальных изображений и ограниченное разнообразие обучающих данных.

Также наблюдалось переобучение: увеличение регуляризации не привело к улучшению результата на тестовых данных.
